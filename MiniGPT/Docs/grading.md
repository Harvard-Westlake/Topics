## <font color="#388bfd">Chapters 1–10</font>

| Component | Weight |
|---|---:|
| Functional correctness | 40% |
| Required tests | 20% |
| Trace or evidence artifact | 15% |
| Explanation of concepts | 15% |
| Code clarity and design | 10% |

Stretch work adds limited bonus credit or substitutes for selected reflection components. It should not allow students with stronger hardware to dominate grades.

A short code-reading interview can be useful for Chapters 6, 8, and 9. Students explain one method chosen by the instructor rather than presenting a rehearsed overview.

## <font color="#388bfd">Capstone (Chapter 11)</font>

Beating the bigram baseline is the engineering target, but it does not determine the entire grade. A correct implementation may miss the target because of:

- Poor learning rate
- Too few training steps
- Unfortunate initialization
- Corpus noise
- Inadequate model width
- Validation variance

The capstone grade emphasizes:

| Category | Suggested weight |
|---|---:|
| Correctness and tests | 25% |
| Experimental design | 20% |
| Evaluation and evidence | 20% |
| Reproducibility | 15% |
| Error analysis | 10% |
| Data and model responsibility | 10% |
