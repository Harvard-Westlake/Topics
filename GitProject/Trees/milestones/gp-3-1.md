# GP-3.1 — Update the Index Format

*Part of the [Trees](../ASSIGNMENT.md) assignment*

---

## Recall

The index currently stores a bare filename for each entry. Trees need the full relative path to build the correct directory hierarchy — they need to know which folder a file is in, not just its name.

---

## Instructions

> **Branch reminder:** What do branches stick out of? Create one.

### Task 1 — Reformat the Index

Update your index entries from bare filenames to relative paths.

**Before:**
```
0acc46ad73849ea9832f600de83a014c9db9cdf0 Cat.java
4377a91cdfd44db9a9bbf056849c7da0fc6cc7be README.md
```

**After:**
```
4377a91cdfd44db9a9bbf056849c7da0fc6cc7be myProgram/README.md
0a4d55a8d778e5022fab701977c5d840bbc486d0 myProgram/Hello.txt
0acc46ad73849ea9832f600de83a014c9db9cdf0 myProgram/scripts/Cat.java
```

### Task 2 — Handle File Addition Edge Cases

Update your `add` method to handle these three cases correctly:

**Case 1 — Exact duplicate** (same file, same path, same content): do nothing.

**Case 2 — Same content, different paths**: add two separate entries with the same hash but different paths.
```
85de840f8b53a6677c4c23e9de47f3b377250cc9 myProgram/Hello.txt
85de840f8b53a6677c4c23e9de47f3b377250cc9 myProgram/scripts/Hello.txt
```

**Case 3 — Same content, different filename**: treat as two separate entries.
```
85de840f8b53a6677c4c23e9de47f3b377250cc9 myProgram/Hello.txt
85de840f8b53a6677c4c23e9de47f3b377250cc9 myProgram/HelloCopy.txt
```

### Task 3 — Handle Modified Files

When a file is modified and staged again, replace its existing index entry with the new hash.

**Before** (`Hello.txt` was staged once):
```
85de840f8b53a6677c4c23e9de47f3b377250cc9 myProgram/Hello.txt
```

**After** (`Hello.txt` was edited and staged again):
```
ca2cb4da9485e7bbce664bf4f5ee2216a36af4fb myProgram/Hello.txt
```
