# GP-4.1 — Identify the Root Tree

*Part of the [Commits](../ASSIGNMENT.md) assignment*

---

## Recall

After Part 3, the program generates tree files and stores the root tree hash. Before building commit support, you need to verify that your partner's tree structure is correct. This manual tracing step confirms you understand the data and reveals any bugs before you build on top of them.

See [Docs/trees.md](../../Docs/trees.md) for a refresher on tree file format.

---

## Instructions

1. Run your partner's tester to:
    - Stage the files
    - Generate blobs and trees based on the index

2. Locate the **root tree** in `git/objects/`. The root tree represents the top-level directory containing all staged files and subdirectories. Its hash may appear in the tester output or a working file.

3. Manually trace all hashes from the root tree:
    - For each `tree <hash> <name>` entry: open that file in `objects/` and verify its contents
    - For each `blob <hash> <name>` entry: confirm the blob file exists in `objects/` and its content matches what you expect

4. Confirm the entire snapshot is intact and accurate.

5. If anything does not work as expected:
    - Document the behavioral bugs in `README.md`
    - Fix the bugs and commit with a label that makes the fix clear
    - You will receive credit for identified and corrected bugs
