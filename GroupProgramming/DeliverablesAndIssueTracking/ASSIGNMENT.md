# Assignment — Deliverables and Issue Tracking

*Lesson: [Deliverables and Issue Tracking](README.md)*

**Due:** Next class

**Points:** 250

---

## Instructions

1. **Track your work** — make sure the issue you were working on last class (and will be working on today) exists on GitHub, is assigned to you alone, and accurately describes the work
2. **Deliver on that issue** — complete the work in its own branch and update the issue's status before next class; if the work turned out to be too big, split the issue and deliver the portion you completed
3. **Review** — if there is work assigned to you for review, review it; **merge the work you reviewed** as evidence of your approval

---

## Success Criteria

Confirm each of the following before submitting:

- [ ] **Issue exists and is yours alone** — the issue is assigned to only you and describes the work you actually did
- [ ] **Work delivered in a branch** — your commits for this issue live in their own branch, not directly on `main`
- [ ] **Issue updated** — the issue's status (In Progress / In Review / Done) reflects reality before next class
- [ ] **Branch or PR linked to the issue** — the branch you worked in (or the pull request into `main`) is linked on the issue
- [ ] **Assigned reviews completed** — any work assigned to you for review has been reviewed, and you merged it as evidence of approval

---

## Submission

Submit **one text response** on Canvas.

### Text response

Copy the stencil below, fill in each line, and paste it into the Canvas text box:

```
Issue URL:                     https://github.com/
Branch or PR URL:              https://github.com/
Issue status at submission:    
Review you performed (URL or "none assigned"):
```

> **Note:**
> Make sure the branch you worked in that is now in `main` (or the pull request that went into `main`) is linked to the issue itself — a grader clicking your issue URL should be able to reach your code in one click.
