# Assignment — Sprint Work

*Lesson: [Sprint Work](README.md)*

**Duration:** 3 class periods  
**Due:** Each sprint is due 2+ hours before the following class

**Points:** 400 per sprint (three sprints)

---

## Instructions

Repeat this cycle each sprint day:

1. **Plan** — with your team, identify the highest-priority tasks, estimate them, break down anything too complex, and assign one task per person as a GitHub Issue
2. **Commit to your task** — make sure it is something you can have *done* 2+ hours before the next class
3. **Work in a branch** — do your task in its own branch with clean, relevant commits
4. **Prove it works** — test what you built; know exactly how you would demonstrate it working
5. **Review** — starting with sprint 2, review at least one teammate's pull request and merge work you approve
6. **If you cannot finish** — call it out *before* time runs out, split the issue into the part you can deliver and the part you push out, and deliver the first part (you will not be downgraded for this)

---

## Grading (400 points per sprint)

- Did you finish your portion and commit the work to GitHub?
- Is there proof that it worked? How can you prove it is working?
  - Are there things which are not working correctly?
  - Have more bugs been identified or introduced?
  - Does it only kind of work?

> **Warning:**
> If you generated code without testing it and it does not work, the maximum grade you can earn for that sprint is **200 points**.

If you committed nothing in class and did not ask for help with reasonable time remaining, that sprint's grade will reflect it. If you flagged the slipping work early and split it honestly, you will not be downgraded.

---

## Success Criteria

Confirm each of the following before each sprint's submission:

- [ ] **Task planned and assigned** — your sprint task exists as an issue assigned to you, chosen by priority and estimated with your team
- [ ] **Work committed in a branch** — your commits for this sprint are pushed in their own branch on GitHub
- [ ] **Proof of working code** — you can demonstrate the work running, and you know which parts (if any) do not work yet
- [ ] **Slippage handled honestly** — if you could not finish, the issue is split into a delivered part and a deferred part
- [ ] **Review completed (sprints 2 and 3)** — you reviewed a teammate's pull request and merged work you approved

---

## Submission

Submit **one text response** on Canvas per sprint.

### Text response

Copy the stencil below, fill in each line, and paste it into the Canvas text box:

```
Sprint number (1, 2, or 3):    
Issue URL:                     https://github.com/
Branch URL(s) for this sprint: https://github.com/
How to see it working:         
Not yet working / known bugs:  
PR you reviewed (sprints 2-3): https://github.com/
```

> **Note:**
> "How to see it working" must be concrete — the exact page to open, button to press, or command to run. "It works" with no way to check is not proof.
