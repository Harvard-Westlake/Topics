# Assignment — Issues as Work Requests

*Lesson: [Issues as Work Requests](README.md)*

**Due:** Next class

**Points:** 300

---

## Instructions

Create **3 high-quality GitHub Issues** that describe **new features or improvements** you want other people to implement on your project.

Each issue must give a receiving programmer enough technical specificity to understand:

1. **Exactly what to build** (precise behavior, not vague goals)
2. **Where it fits** in the project (code area + design link if relevant)
3. **How to verify it works** (clear acceptance tests)
4. **What it depends on** (other PRs, APIs, environment variables, data migrations, libraries, feature flags, etc.)

Use the five-part structure from the lesson in every issue: Summary, Context + where it fits, Detailed requirements, Acceptance criteria, Dependencies — with `Author: [Your Name](profile-link)` as the top line of the body.

When all teammates' issues exist, set priorities as a team so the ranked list is ready for the next round of work.

### Hard rules

- **No AI-generated content in the issues** — including ideas, requirements, acceptance criteria, or steps. AI may be used **only** to format your own content.
- Each issue must include **your name as a clickable link** on the top line of the body.
- Write as if the implementer **cannot ask you questions**.

---

## Success Criteria

Confirm each of the following before submitting:

- [ ] **Three issues created** — all in the correct repository, each describing a distinct feature or improvement
- [ ] **Author line present** — each issue's body opens with your name as a clickable link
- [ ] **All five sections present** — each issue has a summary, context with repo/design links, behavior-first detailed requirements, acceptance criteria, and dependencies
- [ ] **Acceptance criteria are runnable** — each issue has a step-by-step manual test with a happy path, at least one failure/edge case, expected results, and required setup
- [ ] **One correct interpretation** — none of your issues could be implemented in multiple incompatible ways
- [ ] **Content is yours** — no AI-generated ideas, requirements, criteria, or steps anywhere in the issues

> **Warning:**
> If any issue is missing technical requirements, verification steps, or dependencies, it will be treated as incomplete.
