# Review — Tech Spec Components

*Originally covered in [Technical Specification](../README.md)*

---

| Component | Contents |
|---|---|
| **Technology Stack** | Languages, frameworks, tools |
| **Architecture** | How the parts interact |
| **Data Model** | Storage, retrieval, class relationships (drawn graphically) |
| `TechSpec.md` | The three components above, class-wide |
| `<Feature>Spec.md` | Design lines covered; expected variables, methods, related objects |
| `<Feature>Layout.drawio` | Flows, dependencies, color coding + key |
| Folder layout | `documentation/TechSpecs/` |
| Priority rule | Core features (90%) before non-essential (10%) |

---

## Tasks

1. List the three key components of a technical specification and one example item for each.
2. For a feature you know well (e.g. a game's score system), write the Spec.md skeleton: variables, methods, related objects.
3. Sketch the `documentation/TechSpecs/` folder for a project with two features, using correct file-name suffixes.
4. Name one feature from the class design that is core and one that is non-essential, and state the rule that orders them.
