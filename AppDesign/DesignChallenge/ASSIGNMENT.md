# Assignment — The Design Challenge

*Lesson: [The Design Challenge](README.md)*

**Duration:** 2 class periods  
**Due:** Start of the presentation class

---

Design a large-scale web or mobile application/game that is engaging, competitive, and usable by every student in the school. You will present it to your classmates — and one of these designs will be chosen as the class project.

## Submission Requirements (60 pts)

### 1. Public Git Repository (20 pts)

Create a **public** GitHub repository to host the design documentation and any related materials.

- The repository must include a `README.md` containing comprehensive details about the design, functionality, and intended use of the application/game
- The design documentation must be clear, concise, and accessible to an external audience

### 2. Commit History (20 pts)

The repository must have **at least three commits, each made at least an hour apart**.

- This encourages thoughtful, incremental development of the design rather than rushing
- Each commit should represent a significant advancement in the design process, with a clear commit message explaining what changed or was added

### 3. Design Documentation (20 pts)

The `README.md` must include all of the following sections:

| Section | What it covers |
|---|---|
| **Introduction** | A brief overview of the application/game, its purpose, and its target audience |
| **Value/Use** | A clear and explicit explanation of the value or use provided |
| **User Interaction and Experience** | How users will interact with the application/game and what their experience will be like |
| **Competitive Element** | How the application/game facilitates competition among students |
| **Engagement and Addictiveness Strategies** | The features or strategies employed to make it engaging and addictive |
| **Scalability and Expansion** | How the design allows future growth and adoption beyond this assignment |
| **Accessibility and Inclusivity** | How the design adheres to the [California non-discrimination clause](https://tinyurl.com/canondescriminationclause) and ensures inclusivity for all potential users |

---

## Success Criteria

Confirm each of the following before submitting:

- [ ] **Repository is public** — anyone with the link can view it without signing in
- [ ] **All seven README sections present** — each has substantive content, not a placeholder heading
- [ ] **Three or more commits** — timestamps show at least one hour between consecutive commits
- [ ] **Commit messages are meaningful** — each explains what advanced in the design
- [ ] **All five business requirements addressed** — accessibility, explicit value, competition, engagement, scalability
- [ ] **Ready to present** — you can walk the class through the design and answer questions about any part of it
