# Assignment — MVP Planning

**Due:** Next class

---

Cut the combined technical specification down to an MVP and produce the `MVP.md` file that will drive the build.

## Steps

1. Walk the combined spec's **green (core)** items and apply the MVP test to each: *if this were missing, could the end-to-end demo still deliver the core user value?*
2. Assemble the surviving items into an **ordered checklist sorted by dependency** — each item notes what must exist before it can start
3. Split any item too large for one person to make real progress on in one class period
4. Phrase every item as something demonstrable
5. Mark the MVP line clearly; list deferred (yellow and below) items under a **Post-MVP** heading
6. Commit **`MVP.md`** to the root of the class repository in a branch, and open a pull request for the class to review

---

## Success Criteria

Confirm each of the following before submitting:

- [ ] **MVP.md exists at the repo root** — committed in a branch with an open pull request
- [ ] **Every item is demonstrable** — each checklist entry describes something you could show, not a vague system name
- [ ] **Dependency order holds** — no item appears before something it needs
- [ ] **Items are one-person sized** — nothing on the list needs a whole team before progress is visible
- [ ] **The MVP line is explicit** — post-MVP items are present but clearly separated
- [ ] **The MVP is genuinely minimal** — nothing above the line could be removed without breaking the end-to-end demo
