# Review — Design vs Implementation Language

*Originally covered in [Communicating Design](../README.md)*

---

| Design talks about | Implementation talks about |
|---|---|
| User value, behavior, experience | Classes, variables, methods |
| What the product does and why it matters | How the product is built |
| Look, feel, engagement, accessibility | Storage, algorithms, architecture |

Quick test: if a non-programmer cannot picture the sentence, it is implementation.

---

## Tasks

1. Write one sentence of pure design language describing a feature of any app you used today.
2. Rewrite each of these as design language: "the score is stored in an integer," "a timer resets the ghost state," "user data is saved to a database."
3. Sort into design or technical specification: utility, user experience, visual aesthetics, performance and reliability, accessibility, scalability, protecting user data, updatability, engagement.
4. Pick one item you sorted into "technical specification" and explain what a *designer* would say about the same concern.
